Troisième élément de code : le juge. Un second appel au modèle, à qui on demande de noter la fidélité du résumé de 1 à 5, au format JSON. Le code de départ faisait un json.loads direct. Or un modèle de 3 milliards de paramètres entoure presque toujours son JSON de texte, ou l'encadre d'un bloc markdown. Le parsing levait une exception, le score retombait à None, et — c'est le vrai problème — personne ne s'en rendait compte. L'évaluation tournait sans rien mesurer. Notre correction : on extrait le premier objet JSON par expression régulière, et on réessaie une fois en signalant au modèle que sa réponse était invalide. C'est une leçon qu'on a retenue : un échec silencieux dans une chaîne d'évaluation est pire qu'un crash.
